Continue pgTAP for direct cross-user RLS regression. `scripts/test-live-cloudbase.mjs` must not be run as written.
2. **New-Origin Push acceptance:** with browser permission granted by the user, register one real subscription on the shadow Origin, confirm its owner and endpoint uniqueness in PG, send one controlled test notification, and verify receipt/click URL. Leave CloudBase Timer Triggers absent.
3. **Production-Origin gate:** obtain an ICP-compliant custom domain and HTTPS certificate, bind the CloudBase HTTP gateway, update Origin-sensitive Auth/Storage/PWA/Push settings, and repeat a focused authenticated E2E and mainland latency check sized for at most ten daily users. Do not cut over on the default test domain.
4. **Maintenance-window cutover:** freeze Supabase writes, take recoverable backups, re-export/reconcile every table and Storage object, rerun counts/hashes/RLS/pgTAP, disable both Supabase cron jobs, then enable equivalent CloudBase timers, then direct production users to the approved CloudBase domain. Abort and restore the old path if any gate fails.
5. **Rollback and retirement:** monitor for seven stable days with Vercel/Supabase still recoverable. Only after the observation gate, export final database/Storage backups and pause the old services; do not permanently delete Supabase data.
